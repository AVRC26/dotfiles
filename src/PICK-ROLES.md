# PICK-ROLES.md — ayu

Theme being added: **ayu** (`Shatur/neovim-ayu`), flavors `dark`, `mirage`, `light`. `mist`/other variants don't exist for this plugin.

Available Colors are ranked by real Neovim usage (Accent Ranking, see `THEMES.md` "Accent Ranking — objective per-color usage") and filtered to the hue family each Element expects — `SEG0`-`SEG6` follow the reds/oranges/purples/greens/cyans-blues/yellows/muted convention, everything else follows `THEMES.md` "Adding a new theme" step 2's mapping table. Roles other than `OK`/`ERR`/`WARN` avoid reusing a color already recommended for `SEG0`-`SEG6`, so dircolors/git roles get their own identity instead of silently doubling up with a segment color (falls back to allowing it only if no unclaimed candidate exists in that hue family). **Pick** defaults to the Recommended color — edit it to any other name from Available Colors (or any other color in that flavor's palette) if you want something different, then this becomes the `roles.json` `_roles` mapping. **Already Recommended In** lists every other Element (this flavor only) whose Recommended pick is the same color name — sharing a name across roles is a normal, established pattern in this repo (see `THEMES.md` "Color selection philosophy"), not a conflict to avoid.
